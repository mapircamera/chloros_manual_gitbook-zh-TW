# 监控处理过程

处理开始后，Chloros 提供了多种方式来监控进度、检查问题并了解数据集的处理情况。本页面将说明如何跟踪处理进度以及如何解读 Chloros 提供的信息。

## 进度条概述

顶部标题栏中的进度条显示实时处理状态和完成百分比。进度数据通过服务器发送事件（SSE）从后端实时传输，因此进度条准确反映了处理管道的实际运行状况。

### 免费模式进度条

对于未持有 Chloros+ 许可证的用户：

**两阶段进度显示：**

1.**目标检测** - 在图像中查找校准目标
2. **处理** - 应用校正并导出**进度条显示：**

* 总体完成百分比（0-100%）
* 当前阶段名称
* 简单的水平条形可视化

### Chloros+ 进度条

针对拥有 Chloros+ 许可证的用户：

**4 阶段进度显示：**

1.**检测** - 查找校准目标
2. **分析** - 检查图像并准备处理流程
3. **校准** - 应用暗角和反射率校正
4. **导出** - 保存处理后的文件**交互功能：*** **将鼠标悬停**在进度条上，查看展开的 4 阶段面板
* **单击**进度条，可冻结/固定展开的面板
* **再次点击** 可解除冻结，鼠标移开时自动隐藏
* 每个阶段显示独立进度（0-100%）

{% hint style="info" %}
**CLI 奇偶校验**： 在 `chloros-cli process` 运行期间，相同的四个线程均显示为“检测中”、“分析中”、“处理中”和“导出中”，而 `chloros-cli export-status` 则显示来自另一台终端的线程 4 实时导出进度。 请参阅 [CLI 参考指南](../reference/cli-reference.md)。
{% endhint %}

## 了解各个处理阶段

{% hint style="info" %}
**流水线架构**：这 4 个 GUI 阶段对应于 [4 线程处理流水线](../processing-architecture/processing-pipeline.md)。 在支持 GPU 加速的系统上，线程 3（校准）可借助 [动态计算适配](../processing-architecture/dynamic-compute-adaptation.md) 功能，该功能会根据您的具体硬件优化处理流程。
{% endhint %}

### 第 1 阶段：检测（目标检测）

**工作原理：**

* Chloros 会扫描您通过“目标”复选框选中的图像（若未勾选任何选项，则扫描所有图像）
* 计算机视觉算法识别校准面板
* 从每个面板中提取反射率值
* 记录目标时间戳，以便进行正确的校准调度

**耗时：**

* 带有标记目标：10-60 秒
* 没有标记目标：5-30+ 分钟（扫描所有图像）

**进度指示器：**

* 检测中：0% → 100%
* 已扫描图像数量（仅统计实际正在扫描的图像）
* 已发现目标数量

**注意事项：**

* 若目标标记正确，应能快速完成
* 若耗时过长，可能是目标未被正确标记
* 检查调试日志中是否存在“已找到目标”的消息

### 第二阶段：分析

**正在进行的操作：**

* 读取图像 EXIF 元数据（时间戳、曝光设置）
* 根据目标时间戳和可用的数据采集（DAQ）下行数据确定校准策略
* 组织图像处理队列
* 准备并行处理工作者（仅限 Chloros+）

**持续时间：** 5-30 秒**进度指示器：**

* 分析中：0% → 100%
* 该阶段速度较快，通常很快完成

**注意事项：**

* 进度应平稳推进，不应出现停顿
* 关于元数据缺失的警告将显示在调试日志中

### 第三阶段：校准

**正在进行的操作：*** **去拜耳化**：将 RAW 拜耳模式转换为 3 个通道（LATTICE 单色模块将跳过此步骤，并附有说明）
* **暗角校正**：消除镜头边缘变暗现象
* **反射率校准**：根据目标值和/或数据采集（DAQ）下行数据进行归一化
* **指数计算**：计算多光谱指数
* 将每张图像通过完整的处理流程进行处理

**耗时：** 占总处理时间的大部分（60-80%）**进度指示器：**

* 校准中：0% → 100%
* 当前正在处理的图像
* 已处理图像 / 总图像数

**处理行为：*** **自由模式**：按顺序逐张处理图像
* **Chloros+ 模式**： 运行一个硬件自适应工作线程池——在 GPU 系统上（根据 VRAM 容量）有 1 至 4 个并发工作线程，在仅 CPU 系统上，每个物理核心分配一个工作线程（减去一个）。参见 [动态计算自适应](../processing-architecture/dynamic-compute-adaptation.md)
* **GPU 加速**：显著加快此阶段的处理速度**注意事项：**

* 图像计数应保持稳定增长
* 检查调试日志中每张图像的完成消息
* 注意有关图像质量或校准问题的警告

### 第 4 阶段：导出

**处理过程：**

* 处理完成的图像将按选定格式写入磁盘
* **LATTICE**：每帧图像将分发至所有已启用的产品（去拜耳化 / 预览 / 辐射度 / 反射率）
* 导出带有 LUT 色彩的多光谱指数图像
* 创建输出文件夹 `<project>/<camera>/<format>/<Product>_Images/` — 导出文件保留源文件名；文件夹名称标识产品类型

**耗时：** 总处理时间的 10-20%**进度指示器：**

* 导出中：0% → 100%
* 正在写入文件
* 导出格式和目标位置

**需注意的事项：**

* 磁盘空间警告
* 文件写入错误
* 所有配置的输出是否已完成

## 调试日志选项卡

“调试日志”提供了有关处理进度及遇到的任何问题的详细信息。后端启动消息也会重现到日志控制台中，因此即使您较晚打开日志，也能了解整个过程。

### 访问调试日志

1. 点击左侧边栏中的 **调试日志** 图标（<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

）
2. 日志面板将打开，显示实时处理消息
3. 系统会自动滚动以显示最新消息

<!-- SCREENSHOT-NEEDED: Debug Log tab open at the end of a completed run, showing real backend log lines including the [RUN-SUMMARY] lines (images / camera groups / targets / calibrated / files written) -->

### 理解日志消息

以 Chloros 开头的日志行前缀带有方括号中的标签，用于标识子系统——例如 `[PROCESSING]`、`[RUN-SUMMARY]`、`[LATTICE-EXPORT]`、 `[EXPORT-CHECK]`、`[IMPORT-LEVEL]`。最需要了解的是**运行摘要**，它会显示在每次运行的末尾（包括已停止的运行）：

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

每当需要说明时，会跟在后面添加额外的 `[RUN-SUMMARY]` 提示行 ——例如某次运行未生成任何结果，或某台相机的请求产品因不适用而被跳过。`[EXPORT-CHECK]` 行解释了每台相机的跳过情况（例如，为何某台 RGB 相机未获得辐射度产品）。

消息严重性的通用分类（下文示例仅供说明，并非逐字引用）：

#### 信息类消息（白色/灰色）

常规处理更新：处理开始、目标检测（含面板计数）、每帧图像校准进度、文件导出、处理完成。

#### 警告消息（黄色）

不影响处理的非关键问题——例如：帧中缺少GPS数据、目标图像之间存在较大时间戳间隔，或校准面板对比度较低。

**操作：** 处理完成后审查警告，但不要中断处理

#### 错误消息 (Red)

可能导致处理失败的严重问题——例如磁盘已满、图像文件损坏，或在请求反射率校准时未检测到目标。

**操作：** 停止处理，排除错误，重新启动

### 常见日志情况

| 情况                             | 含义                                       | 所需操作                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| 在\[文件名\]中检测到目标        | 成功找到校准目标                                 | 无 - 正常                                         |
| 每张图像的进度条              | 当前进度更新                       | 无 - 正常                                         |
| 未找到目标                      | 未检测到校准目标               | 标记目标图像或禁用反射率校准 |
| 磁盘空间不足               | 输出存储空间不足                 | 释放磁盘空间                                    |
| 跳过损坏的文件               | 图像文件已损坏                         | 从 SD 卡重新复制文件                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | 缺少原始帧的捕获无法处理                        | 请使用原始帧重新捕获，或使用 CLI `--input-level`                        |
| `[RUN-SUMMARY] ... 0 file(s) written` | 运行未生成图像产品 — 报告为失败并附有提示 | 阅读提示信息；检查哪些内容被跳过以及原因 |

### 复制日志数据

若需复制日志以进行故障排除或寻求支持：

1. 打开“调试日志”面板
2. 点击 **“复制日志”** 按钮（或右键单击 → 选择全部）
3. 粘贴到文本文件或电子邮件中
4. 如有需要，发送至 MAPIR 支持团队

## 系统资源监控

### CPU 使用率

**自由模式：**

* 1 个 CPU 核心使用率约为 100%
* 其他核心处于空闲或可用状态
* 系统仍可正常响应

**Chloros+ 并行模式：**

* 多个核心处于高利用率状态——具体数量取决于 [动态计算自适应](../processing-architecture/dynamic-compute-adaptation.md) 所选策略
* 系统响应可能变慢

**监控方法：**

* Windows 任务管理器（Ctrl+Shift+Esc）
* “性能”选项卡 → “CPU”部分
* 查找“Chloros”或“chloros-backend”进程

### 内存（RAM）使用情况

**典型使用情况：**

* 小型项目（&lt; 100 张图像）：2-4 GB
* 中型项目（100-500 张图像）：4-8 GB
* 大型项目（500+ 张图像）：8-16 GB
* Chloros+ 并行模式会占用更多内存

**如果内存不足：**

* 处理更小的批次
* 关闭其他应用程序
* 如果经常处理大型数据集，请升级内存

### GPU 使用情况（Chloros+ 配合 CUDA）

启用 GPU 加速时：

* NVIDIA GPU 显示高利用率（60-90%）
* 显存使用量增加（需 4 GB 以上显存； 若同时进行“Texture Aware”去拜耳化处理则需 7GB 以上）
* 校准阶段速度显著提升

**监控方法：**

* NVIDIA 系统托盘图标
* 任务管理器 → 性能 → GPU
* GPU-Z 或类似监控工具

### 磁盘 I/O

**预期情况：**

* “分析”阶段磁盘读取量高
* “导出”阶段磁盘写入量高
* SSD 速度显著快于 HDD

**性能提示：**

* 尽可能将项目文件夹存放在 SSD 上
* 处理大型数据集时避免使用网络驱动器
* 确保磁盘空间未接近满载（会影响写入速度）

## 处理过程中检测问题

### 预警信号

**进度停滞（5 分钟以上无变化）：**

* 检查调试日志中的错误
* 确认可用磁盘空间
* 检查任务管理器，确保 Chloros 正在运行

**频繁出现错误信息：**

* 停止处理并检查错误
* 常见原因：磁盘空间不足、文件损坏、内存问题
* 请参阅下文的“故障排除”部分

**系统无响应：**

* Chloros+ 并行模式占用了过多资源
* 考虑减少并发任务或升级硬件
* 自由模式对资源的消耗较小

### 何时停止处理

若出现以下情况，请停止处理：

* ❌ “磁盘已满”或“无法写入文件”错误
* ❌ 反复出现的图像文件损坏错误
* ❌ 系统完全死机（无响应）
* ❌ 发现配置设置有误
* ❌ 导入的图像有误

**如何停止：**

1. 点击**“停止”按钮**（取代“开始”按钮）——点击一次即可
2. 进度条显示“正在停止...”的同时，当前处理中的图像将完成处理，随后运行以停止状态结束
3. 已导出的产品仍保留在磁盘上；日志会如实记录已完成内容的 `[RUN-SUMMARY]` 代码
4. 修复问题并重新启动 — 运行将从头开始

## 处理过程中的故障排除

### 处理速度非常慢

**可能原因：**

* 未标记的目标图像（正在扫描所有图像）
* 使用 HDD 而非 SSD 存储
* 系统资源不足
* 配置了过多的索引
* 访问网络驱动器

**解决方案：**

1. 若刚启动且处于“检测”阶段：停止、标记目标、重新启动
2. 未来改进：使用 SSD、减少索引数量、升级硬件
3. 处理大型数据集时，考虑使用 CLI 进行批量处理

### “磁盘空间”警告

**解决方案：**

1. 立即释放磁盘空间
2. 将项目移动到空间更充足的驱动器
3. 减少要导出的索引数量
4. 禁用不需要的 LATTICE 导出产品（项目设置 → 处理）
5. 使用 JPG 格式代替 TIFF（文件更小）

### 频繁出现“文件损坏”提示

**解决方案：**

1. 重新将图像从 SD 卡复制过来以确保文件完整性
2. 检测 SD 卡是否存在错误
3. 从项目中删除损坏的文件
4. 继续处理剩余的图像

### 系统过热 / 降频

**解决方案：**

1. 确保通风良好
2. 清理计算机通风口中的灰尘
3. 降低处理负载（使用“Free”模式代替 Chloros+）
4. 选择一天中较凉爽的时间段进行处理

***

## 处理完成通知

当处理完成时：

* 进度条达到 100%
* 调试日志中出现包含最终计数的 `[RUN-SUMMARY]` 行
* “开始”按钮重新启用
* 所有输出文件均位于项目中各相机的输出目录下：`<project>/<camera>/<format>/<Product>_Images/`

***

## 后续步骤

处理完成后：

1. **查看结果** - 参见 [完成处理](finishing-the-processing.md)
2. **检查输出文件夹** - 确认所有文件均已正确导出
3. **查看调试日志** - 检查是否有警告或错误
4. **预览处理后的图像** - 使用图像查看器或外部软件

有关查看和使用处理结果的信息，请参阅 [完成处理](finishing-the-processing.md)。
