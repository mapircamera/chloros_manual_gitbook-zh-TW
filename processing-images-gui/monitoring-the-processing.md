# 監控處理進度

一旦處理開始，Chloros 便提供多種方式來監控進度、檢查問題，並了解您的資料集當前狀態。本頁說明如何追蹤處理進度，以及如何解讀 Chloros 提供的資訊。

## 進度條概覽

頂部標題列中的進度條會顯示即時處理狀態與完成百分比。進度資料是透過 Server-Sent Events (SSE) 從後端即時傳送而來，因此進度條能真實反映處理流程當下的實際運作狀況。

### 免費模式進度條

針對未持有 Chloros+ 授權的用戶：

**兩階段進度顯示：**

1.**目標偵測** — 在影像中尋找校準目標
2. **處理** — 套用校正並匯出**進度條顯示：**

* 整體完成百分比 (0-100%)
* 當前階段名稱
* 簡單的水平條形視覺化

### Chloros+ 進度條

針對持有 Chloros+ 授權的用戶：

**4 階段進度顯示：**

1.**偵測** — 尋找校準目標
2. **分析** — 檢視影像並準備處理流程
3. **校正** - 套用暗角與反射率校正
4. **匯出** - 儲存處理後的檔案**互動功能：*** **將游標懸停於** 進度條上，即可查看展開的 4 階段面板
* **點擊** 進度條，可凍結／固定展開的面板
* **再次點擊** 以解除凍結，並在滑鼠移開時自動隱藏
* 每個階段皆顯示獨立進度 (0-100%)

{% hint style="info" %}
**命令列介面（CLI）一致性**：在執行 `chloros-cli process` 期間，相同的四個執行緒會分別顯示為「偵測中」、「分析中」、「處理中」和「匯出中」；而 `chloros-cli export-status` 則顯示來自另一台終端的執行緒 4 即時匯出進度。 請參閱 [CLI 參考手冊](../reference/cli-reference.md)。
{% endhint %}

## 了解各處理階段

{% hint style="info" %}
**管線架構**：這 4 個 GUI 階段對應於 [4 執行緒處理管線](../processing-architecture/processing-pipeline.md)。在具備 GPU 加速的系統上， 第 3 執行緒（校準）會運用 [動態運算適應技術](../processing-architecture/dynamic-compute-adaptation.md)，該技術能針對您的特定硬體優化處理流程。
{% endhint %}

### 第 1 階段：偵測（目標偵測）

**運作過程：**

* Chloros 會掃描您勾選了「目標」核取方塊的影像（若未勾選任何項目，則掃描所有影像）
* 電腦視覺演算法會識別校準面板
* 從每個面板中萃取反射率值
* 記錄目標時間戳記，以進行正確的校準排程

**耗時：**

* 標記過目標時：10-60 秒
* 未標記目標時：5-30+ 分鐘（掃描所有影像）

**進度指示器：**

* 偵測中：0% → 100%
* 已掃描的影像數量（僅計入實際正在掃描的影像）
* 已找到的標靶數量

**注意事項：**

* 若標靶標記正確，應能快速完成
* 若耗時過久，可能是標靶未被標記
* 請檢查除錯日誌中的「已找到標靶」訊息

### 第二階段：分析

**處理內容：**

* 讀取影像 EXIF 元資料（時間戳記、曝光設定）
* 根據目標時間戳記及可用的 DAQ 下行數據，確定校準策略
* 組織影像處理佇列
* 準備平行處理工作執行緒 （僅限 Chloros+）

**耗時：** 5-30 秒**進度指示器：**

* 分析中：0% → 100%
* 此階段速度較快，通常很快完成

**注意事項：**

* 進度應穩定推進，無中斷
* 若缺少元資料，警告訊息將出現在除錯日誌中

### 第三階段：校正

**執行內容：*** **去拜耳化**：將 RAW 拜耳圖案轉換為 3 個通道（LATTICE 單色模組會跳過此步驟，並附有註記）
* **暗角校正**：消除鏡頭邊緣變暗現象
* **反射率校正**：根據目標值和／或 DAQ 下行數據進行歸一化
* **指數計算**：計算多光譜指數
* 將每張影像通過完整處理流程進行處理

**耗時：** 佔總處理時間的大部分（60-80%）**進度指示器：**

* 校準中：0% → 100%
* 目前正在處理的影像
* 已處理完畢的影像 / 總影像數

**處理模式：*** **自由模式**：依序逐張處理影像
* **Chloros+ 模式**：運行硬體自適應工作線池 — 在 GPU 系統上（取決於 VRAM）可同時運行 1 至 4 個工作線；在僅 CPU 系統上，則每顆實體核心（減去一個）對應一個工作線。請參閱 [動態運算適應](../processing-architecture/dynamic-compute-adaptation.md)
* **GPU 加速**：顯著加快此階段的處理速度**注意事項：**

* 確認影像計數穩步增加
* 檢查除錯日誌以查看每張影像的完成訊息
* 關於影像品質或校準問題的警告

### 第 4 階段：匯出

**處理內容：**

* 將處理完成的影像以選定的格式寫入磁碟
* **LATTICE**：每幀影像會分流至所有已啟用的產品（去拜耳化／預覽／輻射度／反射率）
* 匯出帶有 LUT 顏色的多光譜指數影像
* 建立輸出目錄樹 `<project>/<camera>/<format>/<Product>_Images/` — 匯出檔案保留原始檔名；資料夾名稱代表產品類型

**耗時：** 總處理時間的 10-20%**進度指示器：**

* 匯出中：0% → 100%
* 正在寫入檔案
* 匯出格式與目的地

**需留意事項：**

* 磁碟空間警告
* 檔案寫入錯誤
* 所有已設定輸出完成

## 「除錯日誌」分頁

「除錯日誌」提供有關處理進度及任何遭遇問題的詳細資訊。後端啟動訊息也會重播至日誌主控台，因此即使您稍晚開啟日誌，也能完整掌握整個過程。

### 存取「除錯日誌」

1. 點擊左側邊欄中的 **除錯日誌** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

圖示
2. 日誌面板將開啟，顯示即時處理訊息
3. 系統會自動捲動以顯示最新訊息

### 理解日誌訊息

Chloros 的日誌行前綴有方括號標籤，用以標示子系統名稱——例如 `[PROCESSING]`、`[RUN-SUMMARY]`、`[LATTICE-EXPORT]`、 `[EXPORT-CHECK]`、`[IMPORT-LEVEL]`。最需要了解的是 **執行摘要**，它會顯示在每次執行結束時（包括已中斷的執行）：

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

每當需要說明時，會跟隨額外的 `[RUN-SUMMARY]` 提示行 — 例如某次執行未產生任何結果， 或是某台相機所請求的產出因不適用而被跳過。`[EXPORT-CHECK]` 行則說明各相機的跳過情況（例如為何某台 RGB 相機未獲得輻照度產出）。

一般訊息的嚴重性等級（以下範例僅供說明，並非逐字引用）：

#### 資訊訊息（白色／灰色）

正常處理更新：處理開始、偵測到目標（附面板計數）、每張影像的校正進度、檔案已匯出、處理完成。

#### 警告訊息（黃色）

不影響處理流程的非關鍵問題 — 例如：幀中缺少 GPS 資料、目標影像之間的時間戳記間隔過大，或校準面板對比度過低。

**處理方式：** 處理完成後檢視警告訊息，但勿中斷處理

#### 錯誤訊息（Red）

可能導致處理失敗的關鍵問題——例如：磁碟空間已滿、影像檔案損毀，或在要求反射率校正時未偵測到目標。

**處理方式：** 停止處理、解決錯誤、重新啟動

### 常見日誌狀況

| 情況                             | 含義                                       | 所需處理                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| 在 \[檔案名稱] 中偵測到標靶        | 成功找到校正標靶                                 | 無 - 正常                                         |
| 每張影像的進度條                    | 當前進度更新                                         | 無 - 正常                                         |
| 未找到標靶                        | 未偵測到校準標靶               | 標記標靶影像或停用反射率校準 |
| 磁碟空間不足               | 輸出空間不足                 | 釋放磁碟空間                                    |
| 跳過損壞的檔案               | 影像檔案已損壞                         | 請從 SD 卡重新複製檔案                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | 缺少原始幀的擷取無法處理 | 請重新擷取並包含原始幀， 或使用 CLI `--input-level`  |
| `[RUN-SUMMARY] ... 0 file(s) written` | 執行後未產生任何影像產出 — 報告為失敗並附提示 | 閱讀提示訊息；檢查哪些步驟被跳過及原因 |
| `[PROCESS] refused: The project folder is too deep for this computer…` | Windows 長路徑功能已關閉，且專案資料夾層級過深，超出 260 字元的路徑限制；未進行任何處理 | 使用較短的專案資料夾 （訊息中會顯示最長且符合限制的路徑），或啟用 Windows 長路徑並重新啟動 Chloros — 請參閱 [啟動處理](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer) |
| `[unmix-clamp-mask] …` | 無法寫入 LATTICE 產品的鉗位遮罩；產品本身無誤且顯示 `Chloros:UnmixClampMask=unavailable` | 請檢查磁碟空間與資料夾權限，若需要該遮罩，請重新處理 |

### 複製日誌資料

若要複製日誌以進行疑難排解或尋求技術支援：

1. 開啟「除錯日誌」面板
2. 點擊 **複製**按鈕（將日誌複製到剪貼簿），或點擊**下載** 將其儲存為文字檔
3. 貼上至文字檔或電子郵件中
4. 如有需要，請寄送至 MAPIR 技術支援

### 從「日誌」分頁回報錯誤

1.3.0 版新增功能：位於「除錯日誌」分頁頂端的錯誤圖示（**回報錯誤**）可直接將報告傳送至 MAPIR。

1. 點擊「除錯日誌」分頁頂端的錯誤圖示
2. 描述問題：您當時的操作、預期結果以及實際發生的情況（必填）
3. 可選擇勾選 **新增幾張圖片（最多 10 張）**，並從開啟的專案中選取圖片，或使用**瀏覽...** 選擇其他圖片檔案
4. 點擊 **傳送**

該報告包含您的描述、所附圖片、Chloros 日誌以及系統詳細資訊（Chloros 版本、作業系統、GPU 及專案設定）。您必須先登入 Chloros（「使用者」分頁）才能發送報告。傳送過程中可關閉視窗； 傳送完成後，日誌中會記錄一個參考編號（例如 `Bug report sent. Reference: BR-…`）——聯絡 MAPIR 時請引用此編號。若報告無法上傳 （例如無網路連線），Chloros 會將其儲存至您的電腦並顯示路徑，以便您透過電子郵件將檔案寄送至 support@mapir.camera。

## 系統資源監控

### CPU 使用率

**自由模式：**

* 1 個 CPU 核心使用率約 100%
* 其他核心處於閒置或可用狀態
* 系統仍可正常響應

** Chloros+ 並行模式：**

* 多個核心處於高使用率狀態 — 具體數量取決於 [動態運算適應](../processing-architecture/dynamic-compute-adaptation.md) 所選的策略
* 系統可能感覺反應較慢

**監控方式：**

* Windows 工作管理員 (Ctrl+Shift+Esc)
* 「效能」標籤頁 → 「CPU」區段
* 尋找「Chloros」或「chloros-backend」程序

### 記憶體 (RAM) 使用率

**典型使用量：**

* 小型專案（< 100 張影像）：2-4 GB
* 中型專案（100-500 張影像）：4-8 GB
* 大型專案（500+ 張影像）：8-16 GB
* Chloros+ 並行模式會消耗更多 RAM

**若記憶體不足：**

* 處理較小的批次
* 關閉其他應用程式
* 若經常處理大型資料集，請升級 RAM

### GPU 使用量（支援 CUDA 的 Chloros+）

當啟用 GPU 加速時：

* NVIDIA GPU 顯示高使用率（60-90%）
* VRAM 使用量增加（需 4 GB 以上 VRAM；若同時執行「Texture Aware」去拜耳化，則需 7 GB 以上）
* 校準階段的速度顯著提升

**監控方式：**

* NVIDIA 系統托盤圖示
* 工作管理員 → 效能 → GPU
* GPU-Z 或類似監控工具

### 磁碟 I/O

**預期情況：**

* 分析階段期間磁碟讀取量高
* 匯出階段期間磁碟寫入量高
* SSD 的速度遠快於 HDD

**效能建議：**

* 盡可能將專案資料夾存放於 SSD
* 處理大型資料集時，避免使用網路磁碟機
* 確保磁碟空間未接近滿載（會影響寫入速度）

## 處理過程中偵測問題

### 警示徵兆

**進度停滯（5 分鐘以上無變化）：**

* 檢查除錯日誌是否有錯誤
* 確認是否有足夠的磁碟空間
* 透過工作管理員確認 Chloros 是否正在執行

**頻繁出現錯誤訊息：**

* 停止處理並檢視錯誤
* 常見原因：磁碟空間不足、檔案損毀、記憶體問題
* 請參閱下方的「疑難排解」章節

**系統無回應：**

* Chloros 的「+」並行模式佔用過多資源
* 考慮減少同時執行的任務或升級硬體
* 「自由模式」對資源的需求較低

### 何時應停止處理

若出現以下情況，請停止處理：

* ❌ 「磁碟已滿」或「無法寫入檔案」錯誤
* ❌ 反覆出現的影像檔案損毀錯誤
* ❌ 系統完全凍結（無回應）
* ❌ 發現設定有誤
* ❌ 匯入錯誤的影像

**如何停止：**

1. 點擊**停止按鈕**（取代「開始」按鈕）——點擊一次即可
2. 進度條會顯示「正在停止...」，待處理中的映像檔完成後，執行程序即以停止狀態結束
3. 已匯出的產品仍保留在磁碟上；日誌會如實記錄已完成內容的 `[RUN-SUMMARY]` 編號
4. 修正問題並重新啟動 — 執行程序將從頭開始

## 處理過程中的疑難排解

### 處理速度非常慢

**可能原因：**

* 未標記目標影像（正在掃描所有影像）
* 使用 HDD 而非 SSD 儲存
* 系統資源不足
* 配置了過多索引
* 存取網路磁碟機

**解決方案：**

1. 若剛開始執行且處於「偵測」階段：停止處理、標記目標影像，然後重新啟動
2. 未來建議：使用 SSD、減少索引數量、升級硬體
3. 考慮使用 CLI 進行大型資料集的批次處理

### 「磁碟空間」警告

**解決方案：**

1. 立即釋放磁碟空間
2. 將專案移至空間較大的磁碟機
3. 減少待匯出的索引數量
4. 停用不需要的 LATTICE 匯出產品（專案設定 → 處理）
5. 使用 JPG 格式取代 TIFF（檔案較小）

### 頻繁出現「檔案損毀」訊息

**解決方案：**

1. 重新將影像從 SD 卡複製過來，以確保資料完整性
2. 檢測 SD 卡是否有錯誤
3. 從專案中移除損壞的檔案
4. 繼續處理剩餘的影像

### 系統過熱／降頻

**解決方案：**

1. 確保通風良好
2. 清理電腦通風口上的灰塵
3. 降低處理負載（使用「Free」模式取代「Chloros+」）
4. 選擇一天中較涼爽的時段進行處理

***

## 處理完成通知

當處理完成時：

* 進度條達到 100%
* 除錯日誌中出現包含最終計數的 `[RUN-SUMMARY]` 行
* 「開始」按鈕重新啟用
* 所有輸出檔案皆位於專案的「每台相機」輸出目錄中：`<project>/<camera>/<format>/<Product>_Images/`

***

## 後續步驟

處理完成後：

1. **檢視結果** - 請參閱 [完成處理](finishing-the-processing.md)
2. **檢查輸出資料夾** - 確認所有檔案均已正確匯出
3. **檢視除錯日誌** — 檢查是否有任何警告或錯誤
4. **預覽處理後的影像** — 使用影像檢視器或外部軟體

有關檢視及使用處理結果的資訊，請參閱 [完成處理](finishing-the-processing.md)。
