# 調整專案設定

在處理影像之前，務必先根據您的工作流程需求配置專案設定。專案設定 <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> 面板可讓您全面控制校正、處理選項、多光譜指標及匯出格式。

## 存取專案設定

1. 在 Chloros 中開啟您的專案
2. 點擊左側邊欄中的 **專案設定** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> 圖示
3. 「專案設定」面板將顯示所有設定選項

<figure><img src="../.gitbook/assets/image (28).png" alt=""><figcaption><p>「專案設定」面板 — 顯示、目標偵測與處理</p></figcaption></figure>

{% hint style="info" %}
**設定會隨專案自動儲存**。當您重新開啟專案時，所有設定都會被還原。
{% endhint %}

***

## 常見工作流程的快速設定

### 預設設定（建議多數使用者採用）

預設設定適用於典型的 Survey3 和 LATTICE 工作流程：

* ✅ **暗角校正**：啟用
* ✅ **暗角校正**：啟用 (使用 MAPIR 標靶和／或 DAQ 光感測器資料)
* ✅ **去拜爾演算法**：標準 (快速、中等品質)
* ✅ **匯出格式**： TIFF（16 位元）（若為全 8 位元專案，則為 TIFF（8 位元））
* ✅ **所有輸出產品**：啟用（LATTICE 會自動將影像拆分並輸出為去拜爾化、預覽、輻照度及反射率檔案）

只需匯入您的影像，並使用這些預設值開始處理即可。

***

## 專案設定概覽

「專案設定」面板分為以下幾個區段。當您的專案包含相關檔案時，另外兩個區段 — **DAQ 光感測器**和**陣列對齊** — 會自動顯示。 完整文件請參閱 [專案設定](../project-settings/project-settings.md)。

### 顯示

* **影像縮圖解析度**：影像網格縮圖的解析度。 選項：**預設 (512 px)**、**1024 px**、**2048 px**、**全解析度**。此設定僅影響顯示，絕不會影響處理流程。數值越高，放大時畫面越清晰，但載入速度會變慢。

### 目標偵測

控制 Chloros 如何在您的影像中識別校準目標。

**關鍵設定：*** **最小校準樣本面積 (px)**：目標偵測的大小閾值（預設：**25**，範圍 0–10000）
* **最小目標聚類值 (0-100)**：將目標區域分組的相似度閾值（預設：**60**）**何時調整：**

* 若出現誤檢，請增加樣本區域
* 若無法偵測到目標，請減少樣本區域
* 若目標被分割成多個偵測結果，請調整聚類閾值

{% hint style="info" %}
當 **反射率校正／白平衡** 關閉時，這些設定會顯示為灰色 — 若關閉此功能，目標偵測將完全無法執行。
{% endhint %}

### 處理

主要影像處理與校正選項。

**關鍵設定：*** **暗角校正**：補償鏡頭邊緣的暗角 ✅ 建議啟用
* **反射率校正／白平衡**：使用偵測到的標靶（Survey3）和／或 DAQ 光感測器資料（LATTICE）對影像進行校正 ✅ 建議啟用
* **去拜爾演算法**：將 RAW 檔案轉換為 3 通道多光譜的演算法
* **最小重新校準間隔**：使用校準標靶之間的最小時間間隔（以秒為單位）（預設：**0** = 全部使用，範圍 0–3600）**未校正的備用產品：**當幀影像無法進行反射率校正時（無可用標靶，或校正功能已停用），該幀將以兩種備用產品之一的形式匯出 ——**每輪運行僅會產生其中一種**，具體取決於「暗角校正」開關的設定：

* **匯出感測器響應**：寫入 `Sensor_Response_Images` — 當「暗角校正」為**關閉** 時使用
* **匯出經暗角校正的資料**：寫入 `Vignette_Corrected_Images` — 當暗角校正功能為**開啟** 時使用

未啟用的核取方塊會顯示為灰色。取消勾選已啟用的選項，將完全停止寫入該檔案。

**LATTICE 匯出產品**（每個專案皆會顯示；適用於 LATTICE 擷取）：

* **匯出去拜耳化影像**： 線性去拜耳化影像（`Debayered_Images`）：先移除校準包的暗場偏移，再進行去拜耳化處理，不包含平場校正或解混——此即擷取時在去拜耳化層級所儲存的原始檔案——並維持感光元件的原生方向。 適用於 RGB 和多光譜模組。
* **匯出預覽**：螢幕預覽畫面（`Preview_Images`）。RGB = 白平衡（若有 DAQ 光源則採用該光源，否則採用灰階世界）+ 伽瑪校正；多光譜 = 假色拉伸。
* **匯出輻度**：float32 光譜輻度（`Radiance_Images`，W/m²/sr/nm）。僅限多光譜模組——不適用於 RGB 主檔。
* **匯出反射率**：uint16 反射率（`Reflectance_Calibrated_Images`，DN 32768 = ρ 1.0），當 `.daq` 下行輻射讀數或畫面內目標覆蓋整個畫面時。 僅限多光譜模組。

這四項皆為 **預設啟用**—— 單一 LATTICE 原始影像在單次處理過程中，會擴展至所有已啟用且適用的產品。當「反射率校正」關閉時，「**匯出反射率**」核取方塊會顯示為灰色。 若其父級開關使該設定無法啟用，該設定將始終呈灰色，並顯示工具提示說明應變更的開關名稱。**進階設定：*** **光感測器時區偏移**：用於光感測器時間對應的 UTC 時數偏移（預設：0，範圍 −12 至 +12）
* **套用 PPK 校正**：使用來自 `.daq` 檔案的 GPS/曝光定位點資料（預設：關閉）
* **曝光定位點 1/2**：將相機指派至曝光定位點，適用於雙鏡頭配置

{% hint style="info" %}
**LATTICE 的輸入等級為自動。** LATTICE 擷取的影像會將其處理等級記錄在 XMP 元資料中，且處理流程總是從原始影像幀開始進入處理管線——GUI 中無需進行任何設定。 （CLI 標誌 `--input-level` 供進階使用者在元資料遺失的擷取檔案中進行覆寫；請參閱 [CLI 參考手冊](../reference/cli-reference.md)。）
{% endhint %}

### 去拜耳化方法

目前 Chloros 提供 2 種去拜耳化方法：

#### 標準 (快速、中等品質)

標準去拜耳化處理速度快，但會產生去拜耳化色彩雜訊，導致影像精確度較低且雜訊較多。

#### 紋理感知（速度較慢，最高品質）\[僅限 Chloros+\]

「紋理感知」採用高品質的邊緣感知去拜爾演算法，並結合 AI/ML 降噪模型，可去除幾乎所有的去拜爾噪點。 該模型運行需佔用 GPU 記憶體（VRAM）：若 **VRAM 容量達 7 GB 或以上**，可同時處理多張影像；若低於 7 GB，則每次僅能處理一張影像（速度明顯較慢）。 請參閱 [動態運算適應](../processing-architecture/dynamic-compute-adaptation.md)。

{% hint style="info" %}
**LATTICE 擷取的影像始終使用「標準去馬賽克」處理。** 目前尚無針對 LATTICE 訓練過的「紋理感知」模型，因此 LATTICE 影像不會提供此選項——但同一專案中的 Survey3 影像仍可使用此功能。
{% endhint %}

### 指數（多光譜指數）

設定要計算並匯出的植被指數。GUI 下拉式選單提供 **27 種預設指數公式**。**如何新增指數：**

1. 點擊**「新增指數」** 按鈕
2. 從下拉式選單中選擇一個指數（NDVI、NDRE、GNDVI 等）
3. 設定視覺化參數（LUT 顏色、數值範圍）
4. 視需要新增多個指數

**常用指數：*** **NDVI**：整體植被健康狀況（最常見）
* **NDRE**： 利用 RedEdge 進行早期壓力檢測* **GNDVI**：對葉綠素濃度敏感
* **OSAVI**：適用於可見光土壤
* **EVI**：葉面積指數 (LAI) 較高的區域

**自訂公式：**

* 透過所有影像波段的數學運算，建立自訂多光譜指標公式
* 儲存自訂公式以供重複使用
* 自訂公式為 Chloros+ 功能；是否可用取決於您的方案等級

有關所有可用指標與公式的詳細資訊——包括哪些名稱僅限於 GUI 使用，哪些亦可在 CLI/SDK 中使用——請參閱 [多光譜指標公式](../project-settings/multispectral-index-formulas.md)。

### 匯出

控制輸出檔案格式。

**可用格式**（設定：**校正影像格式**，預設**TIFF (16 位元)**）：

* **TIFF (16 位元)**：建議用於 GIS 及科學分析
* **TIFF (8 位元)**：8 位元 TIFF
* **TIFF (32 位元，百分比)**：浮點數值
* **PNG (8 位元)**：用於視覺化的無損壓縮
* **JPG (8 位元)**：檔案大小最小，有損壓縮

此清單顯示專案中的影像可支援的位元深度：Chloros 不會提升位元深度。所有 8 位元影像僅提供 TIFF（8 位元）、PNG（8 位元）和 JPG（8 位元）格式，並預設為 TIFF（8 位元）。 在混合專案中，每張擷取影像皆以自身位元深度或更低位元深度匯出。Radiance 則維持 32 位元浮點數格式。

輸出檔案會寫入專案資料夾下，並按相機與格式分組：`<project>/<camera>/<format>/<Product>_Images/`。無論此設定為何，Radiance 皆會 **始終** 以 float32 格式寫入 `tiff32` 資料夾中。 匯出檔案會保留原始檔案名稱——資料夾名稱用以識別產品。LATTICE 多光譜匯出亦可將每像素的裁剪遮罩寫入產品資料夾旁的 `clamp_masks/` 資料夾中。 請參閱 [完成處理](finishing-the-processing.md) 以了解完整的輸出目錄結構。

{% hint style="warning" %}
**讀取反射率值**：表示 ρ = 1.0 的動態範圍 (DN) 取決於原始相機 — LATTICE 使用 32768（標記為 XMP `Chloros:PixelScale`），Survey3 則使用 65535。 請讀取標籤值，而非假設為恆定值。請參閱 [輸出影像格式](../output-image-formats.md)。
{% endhint %}

### DAQ 光感測器

本節列出專案中的每個 DAQ 下行輻射檔案（`.daq` / `.csv`），每行對應一個檔案，顯示感測器型號、檔案名稱，以及該檔案所適用的擴散片 **上限** 校正。

* **遮光罩覆寫（所有檔案）**：一個適用於整個專案的下拉式選單。**自動**（預設）會使用各檔案所記錄的上限值 — 若未記錄任何值，則假設為日照；但 DAQ-U、DAQ-M 和 DAQ-E 出廠時未設定上限值，且 Chloros 無法辨識已擬合的參數，因此處理過程會針對假設的上限值發出警告：請選擇實際已擬合的上限值。 選擇上限值將覆寫所有檔案，唯 DAQ-E-S 除外，因其擴散器是校準的一部分：原始記錄會以此進行校正，而已包含上限值的記錄則會重新參照（撤銷記錄的校正，並套用所選上限值）。
* 當記錄的蓋帽是樞紐預設值而非操作員確認的值時，以及當選取的蓋帽沒有該裝置型號的配置檔時，系統會針對該行發出警告（該檔案將拒絕覆寫）。

在「光感測器」分頁中製作的 DAQ 記錄會自動新增至開啟中的專案，而匯入的 `.daq` / `.csv` 檔案一經新增，即會顯示於此處。

<figure><img src="../.gitbook/assets/image (32).png" alt=""><figcaption><p>下層專案設定 — 索引、匯出格式、「光感測器」資料擷取區段，以及專案範本／資料夾控制項</p></figcaption></figure>### 陣列對齊

此區段**僅**在專案中至少有一張影像攜帶 LATTICE 陣列於擷取時標記的模組間對齊變換（`Chloros:Alignment*` XMP）時才會顯示。 此處會顯示帶有標籤的影像數量以及參考相機，並提供以下控制選項：

* **套用陣列對齊**（預設：開啟）：將每個處理後的產出（去拜耳化／預覽／輻射度／反射率／指數）變形至陣列的共用參考幾何結構。關閉 = 以原生感測器幾何結構匯出。
* **裁切至共同重疊區**（預設：開啟）：將對齊後的輸出裁切至所有模組共有的區域，使每個波段具有相同的覆蓋範圍。關閉時則保留完整的感測器畫布（來源區域外以黑色填充）。
* **重採樣**：**雙線性（平滑，預設）**、**最近鄰（保留精確數值）**— 不進行像素間混合，適用於嚴格的輻射計分析 — 或**三次插值（最銳利）**。***

## 儲存與載入設定

### 儲存專案範本

建立可重複使用的範本，以確保工作流程的一致性：

1. 在「專案設定」面板中配置所有所需設定
2. 捲動至底部的 **「儲存專案範本」** 區段
3. 輸入具描述性的範本名稱（例如：「Survey3N_RGN_Agriculture」）
4. 點擊儲存圖示

**優點：**

* 在多個專案中套用相同的設定
* 與團隊成員分享設定
* 確保重複調查的一致性

### 在新專案中載入範本

建立新專案時：

1. 從主選單中選取 **「新專案」**

2. 在可選用的範本選擇器中選擇一個專案範本
3. 範本中的所有設定將自動套用

### 工作目錄

**「工作目錄」** 設定指定新專案預設的建立位置：

* **預設位置**：Windows「文件」資料夾中的 `Documents\MAPIR\Chloros Projects`（通常為 `C:\Users\[Username]\Documents\MAPIR\Chloros Projects`；若 OneDrive 或漫遊設定檔移動了「文件」資料夾，此位置將隨之變更）
* **變更位置**：點擊編輯圖示並選擇新資料夾
* **與CLI 共用**：`chloros-cli` 採用相同的預設專案資料夾設定
* **Windows 路徑請保持簡短**：除非已啟用 Windows 長路徑功能，否則路徑長度超過約 130 個字元的專案資料夾將在處理前被拒絕 — 請參閱 [開始處理](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer)
* **何時應變更**：
  * 團隊協作用的網路磁碟機
  * 具備更多儲存空間的不同磁碟機
  * 依年份／客戶分類的資料夾結構

## PPK（後處理動態測量）設定

若使用配備 GPS 的 MAPIR DAQ 記錄器進行精確地理定位：

### 先決條件

* 配備 GPS（GNSS）模組的 MAPIR DAQ
* 包含曝光針腳記錄的 .daq 日誌檔案
* 拍攝期間相機已連接至 DAQ 的曝光針腳

### 設定步驟

1. 將 .daq 日誌檔案放置於專案資料夾中
2. 在「專案設定」中，勾選 **「套用 PPK 校正」** 核取方塊
3. 如有需要，請設定 **「光感測器時區偏移」**（預設值：0，代表 UTC）
4. 將相機指派至曝光接腳：
   * **單一相機**：自動指派至接腳 1
   * **雙相機**：手動將每台相機指派至正確的接腳**曝光引腳指派：*** **曝光引腳 1**：從下拉式選單中選擇相機型號
* **曝光引腳 2**：選擇第二台相機或「不使用」
* 同一台相機不得同時指派至兩個引腳

{% hint style="warning" %}
**重要**：曝光接腳必須正確指派給對應的相機。錯誤的指派將導致地理位置資料不正確。
{% endhint %}

## 進階情境

### 多相機專案

當在同一個專案中處理來自多台 MAPIR 相機的影像時：

1. Chloros 會自動偵測每台相機的型號（Survey3 和 LATTICE 皆然）
2. 每台相機將獲得適當的處理設定檔，並擁有各自的輸出資料夾結構
3. PPK：請手動將每台 Survey3 相機指派至正確的曝光針腳
4. 所有相機均採用相同的匯出格式與索引

**範例**：Survey3W RGN + Survey3N OCN 雙相機架組，或混合使用 RGB 主相機與窄帶模組的 LATTICE 陣列

### 定時攝影或多日期調查

針對同一區域隨時間推移進行的重複調查：

1. 建立包含標準設定的範本
2. 每次拍攝均採用一致的校準標靶佈置
3. 將每個拍攝日期作為獨立專案進行處理
4. 使用完全相同的設定以確保結果可比性
5. 採用相同格式匯出以利時間序列分析

### 大型資料集

針對包含大量影像（500+）的專案：

* 考慮按日期或區域拆分為較小的專案
* 使用 Chloros+ 並行處理以加快處理速度
* 考慮使用 CLI 或 API 進行批次自動化
* 調整最小重新校準間隔以縮短標靶偵測時間
