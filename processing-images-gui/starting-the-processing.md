# 开始处理

导入图像、标记校准目标并配置项目设置后，您即可开始处理。本页面将指导您启动 Chloros 处理流程。

## 预处理检查清单

在点击“开始”按钮之前，请确认一切就绪：

* [ ] **文件已导入** - 所有图像均显示在文件浏览器中
* [ ] **目标图像已标记** - 已勾选校准图像的“目标”列 （或已导入用于 LATTICE 的 `.daq` 记录）
* [ ] **已检测到相机型号** - “相机型号”列显示正确的相机
* [ ] **设置已配置** - 已审查并调整项目设置
* [ ] **指数已选择** - 已添加所需的多光谱指数（如需）
* [ ] **导出格式已选定** - 输出格式符合您的工作流程

{% hint style="info" %}
**提示**：在处理前，请在文件浏览器中点击查看几张图像，以验证它们是否已正确加载。
{% endhint %}

## 开始处理

### 查找“开始”按钮

“开始/播放”按钮位于 Chloros 的顶部标题栏中：

* 位置：窗口顶部中央
* 图标：**播放/开始按钮** <img src="../.gitbook/assets/image (2) (1) (1).png" alt="" data-size="line">
* 状态：准备好处理时，按钮处于启用状态（亮起）

### 点击开始

1. 点击顶部标题栏中的 **播放/开始按钮**

2. 处理立即开始
3. 处理过程中，该按钮将变为 **停止** 按钮
4. 进度条实时更新，显示处理状态

{% hint style="success" %}
**处理已启动**：点击后，Chloros 将自动处理所有步骤——目标检测、去拜耳化、校准、索引计算和导出。 它会自动检测您的项目是 Survey3、LATTICE 还是混合类型，并为每台相机应用相应的处理流程。
{% endhint %}

## 了解处理模式

Chloros 根据您的许可证类型，提供两种不同的处理模式：

### 免费模式（顺序处理）

**所有用户均可使用**

**工作原理：**

* 逐张顺序处理图像
* 单线程运行
* 内存占用较低

**进度条显示两个阶段：**

1.**目标检测** - 扫描校准目标
2. **处理** - 应用校准并导出图像**处理时间：**

* 比 Chloros+ 并行模式慢得多
* 适用于中小规模数据集（&lt; 200 张图像）

### Chloros+ 模式（并行处理）

**需要 Chloros+ 许可证**

**工作原理：**

* 通过 [4 线程处理管道](../processing-architecture/processing-pipeline.md) 同时处理多张图像
* [动态计算自适应](../processing-architecture/dynamic-compute-adaptation.md) 会在运行开始时自动为您的硬件选择最佳策略
* 支持 NVIDIA 显卡（台式机和 Jetson）的 GPU（CUDA）加速
* **工作线程数可自适应硬件配置**：GPU 策略运行**1-4 个并发工作线程**（根据 VRAM 容量进行扩展——内存较低的 Jetson 运行 1 个，12GB 以上的台式机 GPU 最多运行 4 个）；纯 CPU 系统则按每个物理核心运行一个工作线程，再减去一个**进度条显示 4 个阶段**（对应 4 个管道线程）：

1. **检测**（线程 1）—— 查找校准目标
2. **分析** （线程 2）—— 检查图像元数据并计算校准参数
3. **校准**（线程 3）—— 去拜耳化、暗角校正、校准、索引计算
4. **导出**（线程 4）—— 保存处理后的图像和索引**进度条交互：*** **将鼠标悬停**在进度条上，可查看详细的 4 个阶段下拉面板
* **点击**进度条，可将下拉面板固定在当前位置
* **再次点击**，可解除固定并隐藏面板**处理时间：**

* 比免费模式快得多
* GPU 加速进一步提升了速度

{% hint style="info" %}
**Chloros+ 速度**：对于大型数据集，并行处理速度可达顺序模式的 5-10 倍。 一个在免费模式下需要 2 小时完成的 500 张图像项目，使用 Chloros+ 可能仅需 15-20 分钟即可完成。
{% endhint %}

## 处理过程中会发生什么

### 第一阶段：目标检测

**Chloros 的功能：**

* 扫描您在“目标”列中勾选的图像（若未勾选任何图像，则扫描所有图像）
* 识别每个目标中的校准面板
* 从目标面板中提取反射率值
* 记录目标时间戳以安排校准

**耗时：** 1-30 秒（已标记目标），5-30+ 分钟（未标记）

### 第二阶段：去拜耳化 （RAW 转换）

**Chloros 的功能：**

* 将 RAW 拜耳阵列数据转换为完整的 3 通道图像（LATTICE 单色模块保持单波段——对其跳过去拜耳化处理，并在日志中注明）
* 应用所选的去拜耳算法
* 最大限度地保留图像质量和细节

**耗时：** 取决于图像数量及 CPU/GPU 速度

### 第三阶段：校准

**Chloros 的功能：*** **暗角校正**：消除边缘处的镜头暗角
* **反射率校准**：使用目标反射率值和/或数据采集（DAQ）下行数据进行归一化
* 对所有波段/通道应用校正
* 根据时间戳为每张图像使用相应的校准参考

**耗时：** 占处理时间的大部分

### 第四阶段：指数计算

**Chloros 的功能：**

* 计算配置的多光谱指数（NDVI、NDRE 等）
* 对校准后的图像应用波段数学运算
* 为每个选定的指数生成指数图像

**耗时：** 每张图像几秒钟

### 第 5 阶段：导出

**Chloros 的功能：**

* 以选定格式保存处理后的图像
* **LATTICE 扇出**：每个原始 LATTICE 帧将一次性导出为所有已启用的产品——去拜耳化、预览、辐射度（始终为 float32）、反射率
* 将文件写入项目输出目录：`<project>/<camera>/<format>/<Product>_Images/`
* **保留源文件名** — 文件夹名称标识产品类型，不添加后缀**处理时长：** 取决于导出格式和文件大小***

## 处理行为

### 自动处理管道

一旦启动，整个处理流程将自动运行：

* 无需用户干预
* 所有配置的步骤按顺序执行
* 实时显示进度更新
* 导出文件在处理完成后立即写入磁盘——您可以在处理仍在进行时打开已完成的输出文件

### 处理过程中的计算机资源占用

**自由模式：**

* CPU 占用率相对较低（单线程）
* 计算机仍可响应其他任务
* 可安全地将 Chloros 最小化，并在其他应用程序中工作

**Chloros+ 并行模式：**

* 策略的工作线程池将占用较高 CPU 资源
* 启用 GPU 加速时：GPU 占用率较高
* 处理期间计算机响应可能变慢
* 请避免启动其他占用大量 CPU 资源的任务

{% hint style="warning" %}
**性能提示**：为获得最佳 Chloros+ 性能，请关闭其他应用程序，让 Chloros 充分利用系统资源。
{% endhint %}

### 处理过程无法暂停 （但可干净地停止）

* 一旦开始，处理过程无法暂停并稍后恢复
* 单击 **停止** 按钮可在首次点击时干净地终止运行
* 停止前已导出的产品仍保留在磁盘上
* 已停止的运行会如实报告已完成的内容 （参见日志中的 `[RUN-SUMMARY]` 行）
* 新运行将从头开始执行处理流程

**规划提示：** 对于非常大的项目，请考虑分批处理或使用 CLI 以获得更好的控制。***

* **查看日志选项卡** - 查看详细的处理消息和警告

## 停止处理

如果您需要停止处理：

### 如何停止

1. 找到 **“停止”按钮**（处理过程中该按钮会替换“开始”按钮）
2. 单击一次 — 进度条将显示 **“正在停止...”**，同时正在处理的图像将完成
3. 该运行将以明确的停止状态结束，日志会如实记录已完成内容的 `[RUN-SUMMARY]`

### 何时停止

**有效的停止理由：**

* 发现使用了错误的设置
* 忘记标记目标图像
* 导入的图像有误
* 系统运行过慢或无响应

**停止后：**

* 停止前已导出的产品仍保留在磁盘上
* 检查并修复任何问题，根据需要调整设置
* 重新启动处理——该运行将从头开始

## 处理时间估算

实际处理时间因以下因素而差异很大：

* 图像数量
* 图像分辨率
* 输入格式（RAW 与 JPG）
* 处理模式（Free 与 Chloros+）
* CPU 速度和核心数
* GPU 可用性（仅限 Chloros+）
* 需计算的索引数量
* 已启用的导出产品数量（LATTICE）

### 粗略估算（Chloros+，12MP 图像，现代 CPU）

| 图像数量 | 免费模式 | Chloros+（CPU） | Chloros+（GPU） |
| ----------- | --------- | -------------- | -------------- |
| 50 张图像   | 15-20 分钟 | 5-8 分钟        | 3-5 分钟        |
| 100 张图片  | 30-40 分钟 | 10-15 分钟      | 5-8 分钟        |
| 200 张图片  | 1-1.5 小时 | 20-30 分钟      | 10-15 分钟      |
| 500 张图片  | 2-3 小时   | 45-60 分钟      | 20-30 分钟      |
| 1000 张图片 | 4-6 小时   | 1.5-2 小时      | 40-60 分钟      |

{% hint style="info" %}
**首次运行**：由于 Chloros 需要构建缓存和配置文件，初始处理可能需要更长时间。后续处理类似数据集时速度会更快。
{% endhint %}

## 启动时的常见问题

### “开始”按钮不可用（呈灰色）

**可能原因：**

* 未导入图像
* 后端未完全启动
* 之前的处理仍在运行
* 项目未完全加载

**解决方案：**

1. 等待后端完全初始化（检查主菜单图标）
2. 确认图像已导入文件浏览器
3. 若按钮仍处于禁用状态，请重启 Chloros
4. 检查调试日志中的错误信息

### 处理开始后立即失败

**可能原因：**

* 项目中没有有效的图像
* 图像文件损坏
* 磁盘空间不足
* 内存（RAM）不足

**解决方案：**

1. 检查调试日志 <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line"> 中的错误信息
2. 确认可用磁盘空间
3. 尝试处理较小的图像子集
4. 确认图像未损坏

### 运行完成但未写入任何图像

请求生成图像产品但未写入任何图像的运行将被视为**失败，而非成功**——Chloros会明确报告此情况：

* GUI 日志中显示的 `[RUN-SUMMARY]` 提示指出了可能的原因——未导入图像、未检测到目标，或所有请求的产品均因不适用而被跳过（例如，从仅支持 RGB 的相机中请求辐射度/反射率）
* CLI 的等效版本（`chloros-cli process`）会输出 `Processing finished but wrote no image products.` 并 **以非零状态退出**，因此脚本可以检测到该情况
* 刻意仅运行元数据（禁用所有导出产品，不生成索引）仍被视为成功

有关完整语义说明，请参阅 [CLI 参考文档](../reference/cli-reference.md#a-run-that-writes-no-images-fails)。

### “未检测到目标”警告

**可能原因：**

* 忘记标记目标图像
* 目标图像中不包含可见目标
* 目标检测设置过于严格

**解决方案：**

1. 参阅 [选择目标图像](choosing-target-images.md)
2. 在“目标”列中标记相应的图像
3. 验证标记的图像中是否可见目标
4. 如有必要，调整目标检测设置

## 成功处理的提示

### 开始之前

1. **先用少量样本进行测试** - 处理 10-20 张图像以验证设置
2. **检查可用磁盘空间** - 确保有 2-3 倍数据集大小的可用空间（如果启用了所有 LATTICE 产品，则需更多空间）
3. **关闭不必要的应用程序** - 释放系统资源
4. **验证目标图像** - 预览已标记的目标以确保质量
5. **保存项目** - 项目会自动保存，但建议手动保存

### 处理过程中

1. **避免系统休眠** - 禁用节能模式
2. **保持 Chloros 处于前台** - 或至少使其在任务栏中可见
3. **不时监控进度** - 检查是否有警告或错误
4. **不要运行其他占用资源的应用程序** - 特别是在使用 Chloros+ 并行模式时

### Chloros+ GPU 加速

如果使用 NVIDIA GPU 加速：

1. 将 NVIDIA 驱动程序更新至最新版本
2. 确保 GPU 拥有 4GB 及以上显存（若需并发进行“纹理感知去拜耳化”，则需 7GB 及以上）
3. 关闭占用大量 GPU 资源的应用程序（游戏、视频编辑等）
4. 监控 GPU 温度（确保散热充足）
