# 開始處理

在您完成影像匯入、標記校準標靶並設定專案參數後，即可開始處理。本頁面將引導您啟動 Chloros 處理流程。

## 預處理檢查清單

在點擊「開始」按鈕之前，請確認一切就緒：

* [ ] **檔案已匯入** - 所有影像均顯示於「檔案瀏覽器」中
* [ ] **標記目標影像** - 已勾選「目標」欄位以標示校正影像（或已匯入 `.daq` 記錄檔供 LATTICE 使用）
* [ ] **已偵測到相機型號** - 「相機型號」欄位顯示正確的相機型號
* [ ] **設定已完成** - 已檢視並調整專案設定
* [ ] **已選取指標** - 已新增所需的多光譜指標（如有需要）
* [ ] **已選擇匯出格式** - 選擇適合您工作流程的輸出格式

{% hint style="info" %}
**提示**：在處理前，請在「檔案瀏覽器」中點選幾張影像，以確認它們已正確載入。
{% endhint %}

## 開始處理

### 尋找「開始」按鈕

「開始／播放」按鈕位於 Chloros 的頂部標題列中：

* 位置：視窗頂部中央
* 圖示：**播放／開始按鈕** <img src="../.gitbook/assets/image (2) (1) (1).png" alt="" data-size="line">
* 狀態：當準備好進行處理時，按鈕會處於啟用狀態（亮起）

### 點擊以開始

1. 點擊頂部標題列中的 **播放/開始按鈕**

2. 處理將立即開始
3. 處理期間，該按鈕會變為 **停止** 按鈕
4. 進度條會即時更新，顯示處理狀態

{% hint style="success" %}
**處理已開始**：點擊後，Chloros 會自動處理所有步驟——目標偵測、去拜耳化、校準、索引計算及匯出。它會自動偵測您的專案是 Survey3、LATTICE 還是兩者混合，並為每台相機套用正確的處理流程。
{% endhint %}

## 了解處理模式

Chloros 會根據您的授權類型，以兩種不同的處理模式運作：

### 免費模式（順序處理）

**所有使用者皆可使用**

**運作方式：**

* 逐張依序處理影像
* 單執行緒運作
* 記憶體佔用較低

**進度條顯示 2 個階段：**

1.**目標偵測** - 掃描校準標靶
2. **處理** - 套用校準並匯出影像**處理時間：**

* 比 Chloros+ 並行模式慢得多
* 適用於中小型資料集（< 200 張影像）

### Chloros+ 模式（並行處理）

**需具備 Chloros+ 授權**

**運作方式：**

* 透過 [4 執行緒處理管線](../processing-architecture/processing-pipeline.md) 同時處理多張影像
* [動態運算適應](../processing-architecture/dynamic-compute-adaptation.md) 會在執行開始時，根據您的硬體自動選擇最佳策略
* 支援 NVIDIA 顯示卡的 GPU (CUDA) 加速
* **工作執行緒數量會根據硬體自動調整**：GPU 策略會運行**2 至 4 個並行工作執行緒**（依 VRAM 容量調整 — 2 至 12GB 的 GPU 為 3 個，12GB 以上的 GPU 為 2 至 4 個）； 純 CPU 系統則每顆實體核心運行一個工作執行緒，再減去一個**進度條顯示 4 個階段**（對應於 4 個管線執行緒）：

1. **偵測**（執行緒 1）— 尋找校準目標
2. **分析**（執行緒 2）— 檢視影像元資料並計算校正參數
3. **校正**（執行緒 3）— 去拜耳化、暗角校正、校正、索引計算
4. **匯出**（執行緒 4）— 儲存處理後的影像與索引

**進度條互動方式：**

* **將滑鼠懸停**於進度條上，即可查看詳細的 4 階段下拉式面板
* **點擊**進度條，可將下拉式面板固定在當前位置
* **再次點擊**，可解除固定並隱藏面板**處理時間：**

* 比免費模式快得多
* GPU 加速可進一步提升速度

{% hint style="info" %}
**Chloros+ 速度**：對於大型資料集，平行處理的速度可比順序模式快 5 至 10 倍。一個在免費模式下需耗時 2 小時的 500 張圖片專案，使用 Chloros+ 可能僅需 15 至 20 分鐘即可完成。
{% endhint %}

## 處理過程說明

### 第一階段：目標偵測

**Chloros 的運作方式：**

* 掃描您在「目標」欄位中勾選的影像（若未勾選任何影像，則掃描所有影像）
* 識別每個目標中的校準面板
* 從目標面板中萃取反射率數值
* 記錄目標的時間戳記以供校準排程使用

**耗時：** 1-30 秒（已標記目標），5-30+ 分鐘（未標記）

### 階段 2：去拜耳化（RAW 轉換）

**Chloros 的運作方式：**

* 將 RAW 拜耳陣列資料轉換為完整的 3 通道影像（LATTICE 單色模組仍維持單波段 — 針對這些模組將跳過去拜耳化處理，並在日誌中註明）
* 套用選定的去拜耳化演算法
* 保留最佳影像品質與細節

**處理時間：** 視影像數量及 CPU/GPU 速度而定

### 第三階段：校正

**Chloros 的功能：**

* **暗角校正**：消除邊緣處的鏡頭暗角
* **反射率校正**：使用目標反射率值和／或 DAQ 下行輻射數據進行歸一化
* 對所有波段／通道套用校正
* 根據時間戳，為每張影像選用適當的校正參考

**處理時間：** 佔處理時間的大部分

### 第 4 階段：指數計算

**Chloros 的處理內容：**

* 計算已設定的多光譜指數（NDVI、NDRE 等）
* 對經校正的影像套用波段運算
* 針對每個選定的指數產生指數影像

**耗時：** 每張影像數秒

### 第 5 階段：匯出

**Chloros 的處理內容：**

* 將處理後的影像儲存為選定的格式
* **LATTICE 扇出**：每個原始 LATTICE 幀將在單次處理中匯出為所有已啟用的產品——去拜耳化、預覽、輻照度（始終為 float32）、反射率
* 將檔案寫入專案輸出目錄：`<project>/<camera>/<format>/<Product>_Images/`
* **保留原始檔名** — 資料夾名稱代表產品類型，不會添加任何後綴**處理時間：** 視匯出格式與檔案大小而定***

## 處理行為

### 自動處理管線

一旦啟動，整個管線將自動運行：

* 無需使用者介入
* 所有已設定的步驟依序執行
* 即時顯示進度更新
* 導出的檔案會在完成時寫入磁碟 — 您可以在處理持續進行的同時開啟已完成的輸出檔案

### 處理期間的電腦資源使用狀況

**免費模式：**

* CPU 使用率相對較低（單執行緒）
* 電腦仍可流暢執行其他任務
* 可安全地將 Chloros 最小化並在其他應用程式中工作

**Chloros+ 並行模式：**

* 策略的工作線池會佔用大量 CPU 資源
* 若啟用 GPU 加速：GPU 使用率將大幅提升
* 處理期間電腦可能較難即時回應
* 請避免執行其他耗用大量 CPU 資源的任務

{% hint style="warning" %}
**效能提示**：為獲得最佳的 Chloros+ 效能，請關閉其他應用程式，讓 Chloros 能充分利用系統資源。
{% endhint %}

### 處理過程無法暫停（但可乾淨俐落地停止）

* 一旦開始，處理過程無法暫停並於稍後恢復
* 點擊 **停止** 將在首次點擊時乾淨俐落地終止執行
* 停止前已匯出的產出檔案仍會保留在磁碟上
* 已停止的執行會如實回報已完成的部分（請參閱日誌中的 `[RUN-SUMMARY]` 行）
* 新的執行會從頭開始執行處理流程

**規劃提示：** 對於非常龐大的專案，請考慮分批處理或使用命令列介面 (CLI) 以獲得更好的控制。***

## 監控您的處理進程

在處理執行期間，您可以：

* **查看進度條** — 查看整體完成百分比
* **查看當前階段** — 偵測、分析、校準或匯出
* **檢查「日誌」分頁** — 查看詳細的處理訊息與警告
* **預覽已完成的影像** — 匯出檔案會在處理過程中出現在磁碟上

有關監控的詳細資訊，請參閱 [監控處理過程](monitoring-the-processing.md)。

## 停止處理

若需停止處理：

### 如何停止

1. 找到 **停止按鈕** （處理期間會取代「開始」按鈕）
2. 點擊一次 — 進度條將顯示 **「正在停止...」**，同時處理中的影像會完成處理
3. 執行程序將以明確的「已停止」狀態結束，且日誌會如實記錄已完成內容（`[RUN-SUMMARY]`）

### 何時應停止

**可接受的停止理由：**

* 發現使用了錯誤的設定
* 忘記標記目標影像
* 匯入了錯誤的影像
* 系統運行過慢或無回應

**停止後：**

* 停止前已匯出的產品仍保留在磁碟上
* 檢視並修正任何問題，並視需要調整設定
* 重新啟動處理 — 執行程序將從頭開始

## 處理時間估算

實際處理時間會因以下因素而有很大差異：

* 影像數量
* 影像解析度
* 輸入格式（RAW 對比 JPG）
* 處理模式 （免費版與 Chloros+）
* CPU 速度與核心數
* GPU 可用性（僅限 Chloros+）
* 需計算的索引數量
* 已啟用的輸出產品數量（LATTICE）

### 粗略估算（Chloros+、12MP 影像、現代 CPU）

| 圖片數量 | 免費模式 | Chloros+ (CPU) | Chloros+ (GPU) |
| ----------- | --------- | -------------- | -------------- |
| 50 張圖片   | 15-20 分鐘 | 5-8 分鐘        | 3-5 分鐘        |
| 100 張圖片  | 30-40 分鐘 | 10-15 分鐘      | 5-8 分鐘        |
| 200 張圖片  | 1-1.5 小時 | 20-30 分鐘      | 10-15 分鐘      |
| 500 張圖片  | 2-3 小時   | 45-60 分鐘      | 20-30 分鐘      |
| 1000 張圖片 | 4-6 小時   | 1.5-2 小時      | 40-60 分鐘      |

{% hint style="info" %}
**首次執行**：由於 Chloros 需建立快取和設定檔，初次處理可能需要較長時間。後續處理類似資料集時將更快。
{% endhint %}

## 啟動時的常見問題

### 「開始」按鈕無法使用（呈灰色）

**可能原因：**

* 未匯入任何影像
* 後端尚未完全啟動
* 先前處理程序仍在執行中
* 專案尚未完全載入

**解決方案：**

1. 等待後端完全初始化（請檢查主選單圖示）
2. 確認影像已匯入「檔案瀏覽器」
3. 若按鈕仍處於停用狀態，請重新啟動 Chloros
4. 檢查除錯日誌中的錯誤訊息

### 處理開始後立即失敗

**可能原因：**

* 專案中沒有有效影像
* 影像檔案損毀
* 磁碟空間不足
* 記憶體（RAM）不足

**解決方案：**

1. 檢查除錯日誌 <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line"> 是否有錯誤訊息
2. 確認可用磁碟空間
3. 嘗試處理較小的影像子集
4. 確認影像未損毀

### 執行完成但未寫入任何影像

若執行程序請求了影像產出但未寫入任何影像，則被視為 **失敗，而非成功** — Chloros 會明確地報告此狀況：

* GUI 日誌會輸出 `[RUN-SUMMARY]` 提示，指出可能的原因 — 未匯入影像、未偵測到目標，或所有請求的產出皆因不適用而被跳過（例如：從僅支援 RGB 的相機請求輻射度／反射率）
* 對應的CLI錯誤（`chloros-cli process`）會輸出 `Processing finished but wrote no image products.` 並 **以非零狀態退出**，因此腳本可偵測此狀況
* 刻意僅輸出元資料的執行（所有匯出產品皆已停用，且無索引）仍被視為成功

請參閱 [CLI 參考手冊](../reference/cli-reference.md#a-run-that-writes-no-images-fails) 以了解完整的語義說明。

### 此電腦的專案資料夾層級過深

**僅限 Windows，1.3.0 版本新增。** Windows 預設關閉長路徑功能，因此任何檔案路徑長度不得超過 260 個字元。Chloros 產出檔案通常位於專案資料夾下方約 130 個字元處，因此若專案資料夾層級超過此限制，便無法接收其產出檔案。為避免執行後未產生任何輸出，Chloros 現於處理開始前會進行檢查：

* 點擊「開始」不會啟動執行： 進度條會顯示原因，而「除錯日誌」中會顯示 `[PROCESS] refused: The project folder is too deep for this computer…`。該訊息會提供專案資料夾的長度，以及符合條件的最長專案資料夾路徑。
* 若在連專案自身檔案都無法容納的過深資料夾中建立或開啟專案，系統亦會拒絕此操作。 系統會顯示訊息方塊說明原因，並標示符合條件的最長專案資料夾名稱以及如何啟用長路徑功能，同時不會建立或開啟任何項目； 除錯日誌會將此情況記錄為 `[PROJECT] refused: …`。若以更長的名稱複製專案，同樣可能超過限制：此時會完成複製但無法開啟，且會顯示相同訊息說明原因。

**解決方案：**

1. 將專案存放於較短的資料夾中 — 在 [專案設定](../project-settings/project-settings.md) 中變更**工作目錄**，並重新建立專案；或
2. 啟用 Windows 長路徑並重新啟動 Chloros：重新執行 Chloros 安裝程式時勾選 **啟用 Windows 長路徑**（此選項預設為勾選狀態），或透過群組原則設定：*電腦設定 > 管理範本 > 系統 > 檔案系統 > 啟用 Win32 長路徑*。

### 「未偵測到目標」警告

**可能原因：**

* 忘記標記目標影像
* 目標影像中未包含可見目標
* 目標偵測設定過於嚴格

**解決方案：**

1. 參閱 [選擇目標影像](choosing-target-images.md)
2. 在「目標」欄位中標記適當的影像
3. 確認標記的影像中可見目標
4. 如有需要，調整目標偵測設定

## 成功處理的訣竅

### 開始前

1. **先以小部分樣本進行測試** - 處理 10 至 20 張影像以驗證設定
2. **檢查可用磁碟空間** - 確保有 2 至 3 倍資料集大小的可用空間（若啟用所有 LATTICE 產品，則需更多空間）
3. **關閉不必要的應用程式** — 釋放系統資源
4. **驗證目標影像** — 預覽已標記的目標以確保品質
5. **儲存專案** — 專案會自動儲存，但建議手動儲存以確保安全

### 處理過程中

1. **避免系統進入睡眠狀態** - 停用省電模式
2. **保持 Chloros 在前台運行** - 或至少讓其顯示在工作列上
3. **不時監控進度** - 檢查是否有警告或錯誤
4. **勿載入其他耗資源的應用程式** - 特別是在 Chloros+ 並行模式下

### Chloros+ GPU 加速

若使用 NVIDIA GPU 加速：

1. 將 NVIDIA 驅動程式更新至最新版本
2. 確保 GPU 具備 4GB 以上 VRAM（若要同時進行「Texture Aware」去拜耳化，則需 7GB 以上）
3. 關閉會大量佔用 GPU 資源的應用程式（遊戲、影片編輯）
4. 監控 GPU 溫度 （確保散熱充足）
